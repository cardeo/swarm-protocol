# System Checks

A System Check is a single SWARM loop applied to a system.

System Checks are for systems where judgment matters more than correctness.

Most work focuses on improving results.

System Checks shift attention to the structure producing those results, especially when there is no clear right answer.

---

## Core Idea

Surface signal in the system, not just the output.

A System Check is a start, not a finish.

It uses one SWARM loop to notice tension, ambiguity, tradeoffs, weak signals, or misalignment in a system.

Use the outcome of the loop to decide where to go next.

---

## What It Actually Does

A System Check does not solve a problem directly.

It:

- directs attention through the system
- exposes weak points and friction
- reveals missing or redundant elements
- surfaces misalignment between parts
- raises follow-up questions
- creates conditions for better decisions

The goal is not completeness or immediate resolution.

The goal is clearer signal about the system itself.

---

## Relationship to SWARM

A System Check does not change the SWARM protocol.

It uses it.

SWARM Loop = structure  
System Check = intent applied to that structure

Each loop still follows:

Spot → Weigh → Arrange → Refine → Make

What changes is how attention is directed inside each step.

---

## Choosing the Right Input

System Checks work best when the input is close to the system being examined.

If there is a clear right answer, you probably do not need a System Check.

If interpretation is required, a System Check may be useful.

Good inputs may include:

- component libraries or Storybooks that are accessible in context
- repositories
- workflows captured in files or artifacts available in the working context
- operating documents that directly shape system behavior

Inputs that are one layer removed from the system may still be useful, but they often reveal documentation or presentation issues rather than the system itself.

If the input is too indirect, the check may drift.

---

## Available System Checks

- Design System — use when the system is a design system, component library, Storybook, design artifact, or product surface shaped by design-system decisions.
- Repository — use when the repo itself is the system being examined: its structure, language, files, docs, naming, and intent.

---

## Attention, Not Instructions

A System Check is not a checklist.

It does not tell you what to do.

It shapes:

- where to look
- what to question
- what to pressure
- what to reconsider

This keeps the loop open and preserves judgment.

---

## Why It Works

Systems often produce consistent problems because their structure is misaligned.

Trying to fix outputs inside a misaligned system creates repeated effort with little improvement.

A System Check:

- increases visibility into the system
- allows patterns to emerge across loops
- creates opportunities for small, high-leverage changes
- creates pressure for additional loops, deeper investigation, or concrete next actions

---

## Signal Formation

A single loop rarely reveals much.

Signal emerges through repetition:

- the same friction appears multiple times
- the same gaps become obvious
- the same improvements keep suggesting themselves

These are signals.

The practitioner decides which signals matter.

Follow the strongest signals into additional loops.

---

## Role of AI

AI can assist by:

- surfacing observations
- suggesting possible weak points
- proposing alternative structures
- highlighting patterns across loops

AI does not determine meaning.

AI explores. Human decides.

---

## What a System Check Is Not

- not a checklist
- not a fixed workflow
- not a guarantee of outcomes
- not a one-pass evaluation
- not an audit
- not a best-practice review
- not a correctness check
- not a complete evaluation

If it feels mechanical, the loop has likely collapsed.

Do not treat a System Check as a complete evaluation.

---

## What It Is

A System Check is a way of directing attention through one SWARM loop to understand the system behind a problem and surface pressure for further loops, follow-up questions, deeper investigation, or concrete next actions.
